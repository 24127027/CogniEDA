# Design decisions

This index records stable reader-facing decisions and their tradeoffs. It is
not an implementation log: **Frozen** and **Approved** describe target
authority, while current support is reported only in the
[status track](../status/current-state.md).

| Decision | Stable summary | Rationale or tradeoff | Status | Affected pages |
| --- | --- | --- | --- | --- |
| Validity-preserving research-state infrastructure | CogniEDA governs typed research state; it is not a chat-memory, notebook, or generic retrieval product. | Restricts convenience features that would blur authority, but preserves traceability and scientific restraint. | **Frozen** | [What is CogniEDA?](../what-is-cognieda.md), [System overview](../architecture/system-overview.md) |
| Exact eight FCOs | The FCO set is exactly Objective, DataProfile, Assumption, Task, Hypothesis, Evidence, Discovery, and SessionFrame. | Keeps durable domain identity small while allowing important non-FCO provenance and operational records. | **Frozen** | [Objects and state layers](../concepts/research-state/objects-and-state-layers.md), [Object catalog](../reference/object-catalog.md) |
| Exact semantic Knowledge Graph membership | The semantic graph contains exactly Objective, Hypothesis, Evidence, and Discovery. SessionFrame and the other FCOs remain outside it. | Prevents workflow, context, and data-state records from masquerading as scientific knowledge. | **Frozen** | [Objects and state layers](../concepts/research-state/objects-and-state-layers.md), [System overview](../architecture/system-overview.md) |
| MVP-v2 is a minimum complete scientific loop | MVP-v2 begins with an adopted dataset and Human intent through Planner, carries one approved scientific investigation through protocol-bound Evidence, evaluation, governance, and semantic graph admission, then survives restart and supports a grounded follow-up. | A smaller analytical demo can prove useful components but cannot prove that CogniEDA preserves scientific authority and continuity end to end. | **Approved** | [MVP-v2 definition](../architecture/mvp-runtime-subset.md), [System overview](../architecture/system-overview.md) |
| Assumption quarantine | Assumptions may guide planning but never enter protected evaluation or Discovery synthesis as inference premises. | Preserves useful framing without converting belief into Evidence. | **Frozen** | [Planning and scientific state](../concepts/research-state/planning-and-scientific-state.md), [Context type safety](../concepts/context/context-type-safety.md) |
| DataProfile immutability | A changed dataset state requires a new DataProfile and explicit lineage; an admitted profile is not rewritten in place. | Costs additional records but keeps every scientific result bound to the data state actually used. | **Frozen** | [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md), [Validity over time](../concepts/validity/validity-over-time.md) |
| Task versus PlanRevision | Task is a semantic work unit. PlanRevision versions plan membership, dependency, assignment, and ordering without changing Task identity; related workflow state owns approval and activation. | Avoids cloning or mutating Tasks for coordination-only changes while keeping lifecycle facts outside immutable plan content. | **Frozen** | [Planning and scientific state](../concepts/research-state/planning-and-scientific-state.md), [Planner architecture](../architecture/planner-architecture.md) |
| PlanTaskBinding and DataProfile ownership V1 | Each member Task has exactly one immutable binding that owns required capability, assigned role, non-negative tie-permitting order rank, and LOW/NORMAL/HIGH priority. PlanRevision does not bind exact DataProfiles; specialists select from complete authoritative context and downstream provenance binds what was actually used. | Keeps Task identity semantic, permits concurrent DAG work without artificial order, and preserves exact lineage at the authority boundary where data is actually selected. | **Frozen** | [Planner architecture](../architecture/planner-architecture.md), [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md), [Contract and cardinality reference](../reference/contract-and-cardinality-reference.md) |
| PlanRevision control semantics V1 | PlanRevision is immutable plan content and contains no configurable stopping conditions, replan triggers, or hypothetical future replan causes. Completion, interruption, approval, activation, and replanning are workflow-lifecycle concerns associated with the revision; scientific and bounded-execution stopping remain in their role-native contracts. | Prevents Planner-authored policy from taking scientific or execution authority and lets later workflow records state the actual typed cause without mutating historical plan content. | **Frozen** | [Planner architecture](../architecture/planner-architecture.md), [End-to-end flow](../architecture/end-to-end-flow.md), [Scientific authority](../concepts/scientific-lifecycle/scientific-authority.md), [Executor and dispatch](../architecture/executor-and-dispatch.md) |
| Planner-only human facade | The Human interacts with the Planner; specialists do not independently converse with the Human. | Centralizes consent and coordination while keeping specialist contracts bounded. | **Frozen** | [Authority boundaries](../architecture/authority-boundaries.md), [End-to-end flow](../architecture/end-to-end-flow.md) |
| Planner scientific non-authority | Planner coordinates and routes but does not author Hypotheses, methods, parameters, decision rules, protocols, Evidence obligations, or protected evaluation. | Separates project coordination from scientific commitment. | **Frozen** | [Authority boundaries](../architecture/authority-boundaries.md), [Scientific authority](../concepts/scientific-lifecycle/scientific-authority.md) |
| Data Explorer exclusive dataset access | All dataset reads and bounded data operations pass through Data Explorer under an admitted work order. | Adds an explicit handoff but prevents hidden or untraceable data access. | **Frozen** | [Executor and dispatch](../architecture/executor-and-dispatch.md), [Evidence and AnalysisFrames](../concepts/scientific-lifecycle/evidence-and-analysis-frames.md) |
| Hypothesis Analyst scientific ownership | Hypothesis Analyst owns feasibility, scientific operationalization, protocol, Evidence obligations, and protected evaluation, without direct dataset access. | Keeps one scientific authority while requiring observation through Data Explorer. | **Frozen** | [Scientific authority](../concepts/scientific-lifecycle/scientific-authority.md), [Protected evaluation](../concepts/scientific-lifecycle/protected-evaluation.md) |
| Graph Miner read-only boundary | Graph Miner may inspect Objective-scoped typed paths, gaps, conflicts, dependencies, and validity, but may not mutate state or create Evidence or Discovery. | Enables graph assistance without granting admission or scientific authority. | **Frozen** | [Executor and dispatch](../architecture/executor-and-dispatch.md), [Retrieval strategy](../concepts/context/retrieval-strategy.md) |
| Application-authority admission | Agents propose or return bounded results; application authority validates identity, contracts, lineage, authorization, and transactions before durable admission. | Requires explicit services and validation but prevents model output from becoming authoritative by assertion. | **Frozen** | [Persistence and admission](../architecture/persistence-and-admission.md), [Authority boundaries](../architecture/authority-boundaries.md) |
| Scientific cardinalities | An eligible feasible leaf SCIENTIFIC Task produces exactly one Hypothesis; an infeasible Task produces none. A Hypothesis produces zero or one Discovery. Parent Tasks produce neither. | Gives feasible scientific work one unambiguous commitment while permitting legitimate non-completion without a fabricated Discovery. | **Frozen** | [Contract and cardinality reference](../reference/contract-and-cardinality-reference.md), [Scientific lifecycle](../concepts/scientific-lifecycle/index.md) |
| Typed non-Discovery outcomes | A governed investigation may end in a typed non-Discovery outcome rather than a fabricated claim. | Preserves negative, blocked, and incomplete knowledge without inflating the semantic graph. | **Frozen** | [Protected evaluation](../concepts/scientific-lifecycle/protected-evaluation.md), [Lifecycle and outcome catalog](../reference/lifecycle-and-outcome-catalog.md) |
| Valuable-inconclusive eligibility | A scientifically valuable inconclusive result may be proposed as a scoped Discovery when its evidence, claim, and validity basis satisfy the same governance and admission rules. | Preserves useful knowledge about evidential limits while prohibiting a stronger unsupported claim. | **Frozen** | [Protected evaluation](../concepts/scientific-lifecycle/protected-evaluation.md), [Discovery governance](../concepts/scientific-lifecycle/discovery-governance.md) |
| Structural-only canonicalization | Canonicalization may validate, order, serialize, bind versions, reject duplicates, and digest; it may not infer semantic equivalence or repair meaning. | Rejects some potentially reconcilable inputs in exchange for deterministic, reviewable identity. | **Frozen** | [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md), [Persistence and admission](../architecture/persistence-and-admission.md) |
| Cross-Objective isolation | Objective boundaries fail closed. Similarity, shared Workspace, or graph proximity does not grant reuse or relation authority. | Limits opportunistic reuse but prevents cross-scope contamination. | **Frozen** | [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md), [Retrieval strategy](../concepts/context/retrieval-strategy.md) |
| Exact cross-Objective Evidence reuse | Reuse requires explicit admission and exact equality of the canonical Evidence identity and lineage contract; fuzzy equivalence is insufficient. | Makes reuse stricter and more expensive but keeps scientific meaning intact. | **Frozen** | [SessionFrame](../concepts/context/session-frame.md), [Validity propagation](../concepts/validity/validity-propagation.md) |
| SessionFrame governs Planner visibility | Every object retained in SessionFrame is resolved into Planner context. Context construction may add authorized supplemental material but may not filter, rank away, or truncate retained membership; type, lifecycle, validity, scope, lineage, and authority constrain use rather than visibility. | Preserves user-governed continuity while requiring separate authority-built inputs for protected scientific operations. | **Frozen** | [SessionFrame](../concepts/context/session-frame.md), [Context type safety](../concepts/context/context-type-safety.md), [Retrieval strategy](../concepts/context/retrieval-strategy.md) |
| Historical truth versus current authority | Historical records preserve what happened; separate lifecycle and validity state determines whether they may be used now. | Retains audit history without allowing stale or invalid state into protected reasoning. | **Frozen** | [Validity over time](../concepts/validity/validity-over-time.md), [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md) |
| Multiple Objectives per Workspace | A Workspace may contain multiple active Objectives; Workspace is a container, not a global scientific scope. | Supports concurrent research while requiring explicit Objective binding. | **Approved** | [Context](../concepts/context/index.md), [Continuity and resume](../concepts/context/continuity-and-resume.md) |
| Workspace physical ownership | The resolved path opened by the user is the research Workspace. Conventional user-managed datasets belong under its `data/` directory, CogniEDA-private operational state belongs under `.cognieda/`, and explicit external datasets remain possible. | Prevents the product repository or installation from masquerading as research-project state while keeping physical location distinct from admission. | **Frozen** | [Workspace ownership](../development/workspace-layout.md), [Identity, scope, and lineage](../concepts/research-state/identity-scope-and-lineage.md) |
| One active Planner session per Objective | In the current architecture phase, at most one active Planner session owns coordination for an Objective; different Objectives may proceed concurrently. | Simplifies plan and approval concurrency while preserving Workspace-level parallelism. | **Approved current-phase constraint** | [Continuity and resume](../concepts/context/continuity-and-resume.md), [Context](../concepts/context/index.md) |
| Hard cutover and fail closed | Canonical new writes accept only canonical contracts. Legacy shapes are historical provenance, not fallback authority; ambiguous or incomplete input is rejected. | Sacrifices compatibility convenience to prevent silent semantic corruption. | **Frozen** | [Persistence and admission](../architecture/persistence-and-admission.md), [Contract and cardinality reference](../reference/contract-and-cardinality-reference.md) |
| No product CLI in the current phase | The current phase does not expose a supported CogniEDA product CLI. Internal development helpers do not change that boundary. | Keeps effort on validity, authority, and traceable runtime contracts before interface breadth. | **Approved current-phase constraint** | [Current state](../status/current-state.md), [Future improvements](../status/future-improvements.md) |

## How to use this index

When implementation and a frozen decision differ, document the difference in
the status track; do not reinterpret the decision to match the code. When a
decision is not listed as frozen or approved, describe it as exploratory or
unresolved until an authoritative public decision is recorded.
